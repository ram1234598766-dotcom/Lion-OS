# LionOS Month 6 (v1.0.0) Implementation Plan — Path A

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Checkboxes = tracking.

**Goal:** Ship v1.0.0 Path A — a self-hosted windowing app layer on the Month-4/5 base: a **dock**, **theming**, a **file explorer**, an **editor**, and a simulated **AI stub**. Everything still boots in QEMU with the suite green.

**Architecture:** extends `ffd7797` (M5: Canvas/compositor/wallpaper/input). The kernel now has a safe `gfx::Canvas` + a painter compositor and a read-only FAT32 driver (`fs.rs`, `drivers/ide.rs`, `virtio_blk`) + ring-3 syscalls. Month 6 is the *application layer*: plain structs + the FAT read path + the compositor, host-tested where they are syscall/debug-agnostic, with serial markers otherwise.

**Tech Stack:** Rust (nightly `x86_64-unknown-none`), the FAT reader, the compositor, qemu 10.2.2. Kali for build/commit; Git Bash (Windows) for read/edit/push.

## Global Constraints
- Build in Kali (`cd kernel && cargo build`; `cd ../os && cargo build` → `target/bios.img`); host tests `cargo test --target x86_64-unknown-linux-gnu`; boot `qemu … -vga std -serial file:…`.
- Deterministic `LIONOS_` boot markers; add new ones to `.github/workflows/ci.yml`.
- MMIO/VGA through the phys window; `#[cfg(target_os="none")]` for hardware; pure logic host-tested.
- **FAT is read-only and often unmounted** in the standard single-drive boot (`LIONOS_FS_NONE_MOUNTED`), so explorer markers must not *require* a mounted volume — exercise with a synthetic model (host-tested) and print the honest `NO_DISK` path at boot.

### Task 1: `ai.rs` — the simulated assistant (honest stub, no ML)
**Files:** `kernel/src/ai.rs` (pure), `main.rs` boot marker.
- [ ] `pub fn answer(prompt: &str) -> &'static str` — case-insensitive keyword match ("hello/hi", "help", "time") → deterministic canned replies; unknown → "simulated: canned only". No allocation (`ci_contains` over bytes).
- [ ] Host tests: greeting/help/empty/unknown branches; case-insensitivity.
- [ ] Boot marker `LIONOS_AI_STUB reply="LionOS AI ready"` (ask "hello").
- [ ] Register `pub mod ai;`. CI greps the marker.

### Task 2: Theming (`theme.rs`)
- [ ] A `Theme { bg, fg, accent, focus_border }` palette; `apply(theme, &mut [Window])` recolors windows; a built-in default + a dark variant.
- [ ] Host tests: applying themes sets window colors; `LIONOS_THEME name=…`.

### Task 3: File explorer + editor (FAT-backed, synthetic fallback)
- [ ] `explorer.rs`: walk the mounted `fs::Fs` (or a synthetic dir list when `NO_DISK`) into a `Vec<DirEntry>`; `render(compositor)` draws the first lines; `LIONOS_EXPLORER nfiles=…` / `LIONOS_FS_NONE_MOUNTED` when absent.
- [ ] `editor.rs`: a line-edit `TextBuffer` (insert/backspace/`^` cursor) host-tested; persists via FAT if a disk is there; `LIONOS_EDITOR buf_len=…`.

### Task 4: dock + `v1.0.0` release
- [ ] `dock.rs`: a bottom bar of app buttons (explorer/editor/ai/theme) via the compositor; `LIONOS_DOCK napps=…`.
- [ ] Release ritual → `v1.0.0` (README/Changelog/tag/GHCR/release), license All-Rights-Reserved.
