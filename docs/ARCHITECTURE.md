# LionOS Architecture

Work-in-progress; sections fill in as each subsystem lands. Status reflects the
**current** state of the tree, per the six-month plan.

## 1. Boot Process *(M1W3 — real handoff)*

**Firmware → bootloader → kernel handoff**, faithfully recorded as it stands:

1. **Power-on → SeaBIOS (BIOS)** boots the disk image. (UEFI/OVMF is not yet in
   the boot path — the `os/`-built image is BIOS. UEFI via `UefiBoot` is a
   later-month addition; the GOP framebuffer handoff already ships on the BIOS
   path.)
2. **Boot provider = upstream `bootloader` crate v0.11.17**, built into a disk
   image by the `os/` builder crate (`BiosBoot` DiskImageBuilder; the kernel
   ELF is a build **artifact** dependency). It reads the BIOS memory map, sets
   up initial 4-level page tables, enters long mode, provides a stack, and
   hands a structured `BootInfo` to the kernel entry.
3. **Kernel `kernel_main(&'static mut BootInfo)`** (the exported symbol
   `_start` is generated by `bootloader_api::entry_point!`). It re-validates
   the memory map (defense in depth, `kernel/src/memory.rs`), validates the
   framebuffer descriptor and draws a test pattern through the C library,
   exercises the C/asm bridge, prints summaries over COM1
   (`LIONOS_MEM_MAP regions=N usable=M`, `LIONOS_FB_OK`, `LIONOS_FB_DRAW_OK`,
   `LIONOS_CPUID_LEAF1EDX=…`, `LIONOS_ASM rflags=…`, then `LIONOS_HANDOFF_OK`),
   preserves the Week-1 checkpoint marker `LIONOS_INIT_OK`, and parks the CPU.
   No interrupts, no heap, no user mode yet (Month 2).

### The handoff data

`BootInfo` (bootloader 0.11.17) carries `memory_regions: MemoryRegions` of
**byte-address** `MemoryRegion { start, end, kind }` entries (exclusive `end`,
`MemoryRegionKind: Usable | Bootloader | UnknownUefi(_) | UnknownBios(_)` —
non-exhaustive). `kernel_main` adapts each into a `(start, end, kind)` triple
and feeds it to `lionos_kernel::memory::validate_regions_bytes`, which rejects
malformed input (zero-length, >64 entries, overlapping **usable** regions) and
returns sorted byte-address regions. The frame-number-based `validate_regions`
is kept for the fuzz/host-test path that models the 0.9.35 shape. The same pure
functions are unit-tested on the host and fuzzed with `cargo-fuzz`.

`BootInfo` also carries `framebuffer: Optional<FrameBuffer>` (the GOP handoff)
and `physical_memory_offset: Optional<u64>` (None with the default
`BootloaderConfig`; only set if `mappings.physical_memory` is configured).

The bootloader's page tables are the **boot provider's** until the Month-2
takeover: the kernel enables `mappings.physical_memory` in its
`BootloaderConfig`, and `paging::takeover` then builds the kernel's **own** PML4
(copying the bootloader's 512 top-level entries through the physical-memory
window) and loads CR3 with its physical address. From then on the kernel owns
the page tables (see §2).

### Mixed-language (C + assembly) support *(M1 refinement, deepened)*

Beyond the Rust core, a guarded slice of low-level support is written in
freestanding C (`kernel/c/support.c` — memset/memcpy/memcmp + a C→asm CPUID
helper; `kernel/c/fb.c` — framebuffer drawing) and assembly (`kernel/asm/cpu.s`
— hlt/cli/sti/pause/read_cr3/cpuid/read_msr/write_msr/read_rflags/inb/outb/
xchg8). `kernel/build.rs` compiles both into a static lib with
`-ffreestanding -fno-builtin -fno-stack-protector -mno-red-zone -mcmodel=kernel
-fno-pie -nostdlib -nostdinc`, kept to the freestanding `x86_64-unknown-none`
target only, and links it into the kernel ELF. The Rust side declares them in
`kernel/src/ffi.rs` and calls them through safe wrappers.

The call graph is deliberately layered so every half of the mixed-language
stack is exercised at boot and asserted in CI:

- **Rust → C**: `fb_clear` / `fb_fill_rect` / `fb_hline` / `fb_pixel` draw a
  test pattern into the validated framebuffer (`LIONOS_FB_DRAW_OK`); the C code
  bounds-checks every pixel so a malformed descriptor can never write outside
  the mapped buffer.
- **C → assembly**: `support.c::lion_cpu_leaf1_edx` calls the asm `lion_cpuid`
  (`LIONOS_CPUID_LEAF1EDX=…`) — the full Rust→C→asm chain in one call.
- **Rust → assembly**: `read_rflags` (deterministic `0x2` at boot, IF=0),
  `read_msr(EFER)`, and an atomic spinlock round-trip via `xchg8`
  (`LIONOS_ASM rflags=… efer=… spin=1`).

CI greps the deterministic markers (`memset=abababababababab`, `memcpy_ok=1`,
`LIONOS_FB_DRAW_OK`, `LIONOS_CPUID_LEAF1EDX=`, `LIONOS_ASM rflags=…`, `spin=1`)
so a silent regression in any layer fails loudly instead of weeks later.

> **Watch note (M1 refinement, fixed):** the first `cpuid` stub triple-faulted.
> `CPUID` overwrites `EDX`, but SysV had parked the `out` pointer in `%rdx`; the
> `mov %eax,(%rdx)` then wrote through the clobbered `EDX` (≈ the CPUID feature
> bits) → `#PF` → double/triple fault. Fix: stage the `out` base in `%r8`
> (which `CPUID` does **not** clobber) before executing.

### Build flags that matter

The kernel uses the builtin `x86_64-unknown-none` target, but must be linked
**non-PIE at 1 MiB** or it cannot boot: the default build emits a
position-independent ELF (segments at VMA 0) that the bootloader jumps into and
immediately faults. The rustflags live at the **workspace root**
`.cargo/config.toml` under `[target.x86_64-unknown-none]`:
`-C relocation-model=static` + `-C link-arg=-no-pie`, with `kernel/linker.ld`
passed by **absolute path** from `kernel/build.rs`
(`cargo:rustc-link-arg=-T<CARGO_MANIFEST_DIR>/linker.ld`).

Why the root, not `kernel/.cargo/config.toml`: the kernel is also built as a
build **artifact** by `os/`, and cargo discovers config from the invocation
directory **upward** — a `kernel/.cargo/config.toml` would never be seen when
`os/` builds the kernel, silently dropping the rustflags (PIE kernel at VMA 0,
won't boot). Scoping under `[target.x86_64-unknown-none]` keeps the flags off
every host build (`launcher`, `fuzz`, `os`); the absolute linker-script path is
required because the artifact link's cwd is `os/target/…`, not the repo root.

> **Watch note (M1W3, fixed):** with `-no-pie` and more complex kernel code, the
> linker emitted a `.got`/`.data.rel.ro` RELRO segment at a **non-4KiB-aligned
> VMA** (`0x10b6e8`). The bootloader maps kernels by page-aligned program
> headers, so that segment made it mis-map pages and the kernel never entered
> `_start` (silent hang after "Booting (second stage)…"). Fixed by folding
> `.got`/`.got.plt`/`.data.rel.ro` into `.data` in `kernel/linker.ld`, so every
> LOAD segment is 4KiB-aligned. Symptom to remember: any silent
> "boots to second stage then nothing" is a load-segment mis-map — check
> `readelf -lW` for non-aligned LOAD VMAs first.
>

### Memory layout *(real addresses from `readelf`/`objdump`, debug build)*

| Section / symbol | Address (VMA) | Notes |
|------------------|---------------|-------|
| Entry point      | `0x101510`    | `_start` (generated by `entry_point!`) — varies per build |
| `.text`          | `0x100000`    | kernel code (`lib` + bin) |
| `.rodata`        | `0x10b000`    | marker strings, `HEX` table |
| `.bootloader-config` | `0x10e000` | 0.11 loader config — MUST survive linking (KEEP) |
| `.data`          | `0x10f000`    | `.got`/`.data.rel.ro` folded in (M1W3 fix) |
| `.bss`           | —             | empty in the placeholder |

Addresses are build-dependent (they shift as code grows); re-derive from
`readelf -hS` on the current ELF rather than trusting this table.

Debug sections (`.debug_*`) have VMA 0 and are not loaded into memory. The
canonical load base is the bootloader's decision; it currently places the
kernel at ~`0x401000` physical and identity-maps it.

## 2. Memory & CPU — *Month 2 (shipped)*

Month 2 brings the kernel's own CPU-core + memory primitives up behind `sti`.

### Interrupts *(W1, W3 — shipped)*
- **GDT + TSS/IST** (`gdt.rs`): after the paging takeover maps writable pages,
  `gdt::setup()` installs a custom GDT (null / code64 / data64 / 64-bit TSS) and
  `ltr`s the TSS. The TSS's `IST0` points at a dedicated double-fault stack, and
  the IDT's double-fault gate (vector 0x08) selects IST1 — so a fault *inside* a
  fault handler no longer triple-faults on the same stack. Boot marker:
  `LIONOS_GDT_OK ist0=…`.
- **IDT** (`idt.rs`): 256 gates; exception vectors 0x00/0x06/0x08/0x0D/0x0E print
  structured diagnostics (`LIONOS_FAULT vector=…`, CR2 on #PF) instead of a
  silent triple fault.
- **8259 PIC remap + 8254 PIT + PS/2 keyboard** (`interrupts.rs`): IRQs become
  IDT vectors 0x20..0x2F; timer (100 Hz) and keyboard ISRs do tiny work and push
  to a bounded *deferred-work queue* drained from the idle loop. Boot markers:
  `LIONOS_IRQ_FLAGS=…206` (IF=1), `LIONOS_TIMER_TICKS=25`, `LIONOS_IRQ_OK`.

### Memory *(W2 — shipped)*
- **Frame allocator** (`frames.rs`): free-list over validated *usable* regions,
  floor at kernel `_end`; alloc/dealloc by frame number (accounting only).
- **Paging takeover** (`paging.rs`, `LIONOS_TAKEOVER cr3=…`): the M2W3c unblock.
  The kernel enables `mappings.physical_memory` in its `BootloaderConfig`
  (`main.rs` `BOOT_CONFIG`), so `BootInfo.physical_memory_offset` exposes a
  virtual window over the whole physical address space. `paging::takeover`
  allocates the kernel's own PML4, copies the bootloader's 512 top-level entries
  through that window, and loads CR3 with the new PML4's *physical* address —
  the kernel now owns the page tables. `map_page`/`translate`/`map_range` build
  new mappings (allocating intermediate table frames). Verified at boot:
  `LIONOS_MAP_RW back=deadbeefcafef00d phys_ok=1` (map → write → read → translate).
- **Heap** (`heap.rs`, `LIONOS_HEAP_OK cap=…`): a hand-rolled first-fit
  free-list `#[global_allocator]`, now **frame-backed**: `init_heap` maps
  `HEAP_SIZE` of physical frames at a fresh 512 GiB region (via `map_range`)
  instead of a baked-in `.bss` array — the concrete payoff of owning paging.
